Pero que es el límite de compilación El límite de compilación (en inglés lo encuentras como Build Limit o Build Minutes) es, en palabras sencillas, el tiempo máximo al mes que la plataforma te presta sus computadoras para armar tu página. Para entenderlo de forma muy clara, imagínalo con esta analogía: 🛠️ La analogía del taller: Tu código de React es como los planos de un mueble. Para que la gente lo pueda usar, alguien tiene que armar ese mueble. Como tu computadora local no es la que va a tener guardada la página en internet, Netlify o Vercel ponen a un "carpintero" (un servidor de ellos) a armar tu proyecto cada vez que haces un git push. El límite de compilación es el tiempo total que ese carpintero tiene permitido trabajar para ti de forma gratuita durante el mes. ¿Cómo se consume ese límite? Cada vez que tú haces un git push, pasa lo siguiente: El servidor de Netlify o Vercel se enciende. Descarga tu código de GitHub. Instala los paquetes de Node (npm install), optimiza tus imágenes, limpia el código de React y lo convierte en archivos HTML, CSS y JS puros (el comando npm run build). Este proceso tarda, por ejemplo, 1 minuto. El servidor se apaga. Si Netlify te da 300 minutos al mes, significa que tienes 300 minutos de ese temporizador corriendo. Si cada intento tuyo tarda 1 minuto, gastaste 1 minuto de tu bolsa mensual y te quedan 299 minutos libres para el resto del mes. ¿Qué pasa cuando la gente entra a visitar tu página? ¡Nada! Las visitas no gastan minutos de compilación. Una vez que el proyecto ya está compilado y guardado en internet, los servidores no tienen que volver a armar nada. Los usuarios entran directo a ver el resultado. El límite de visitas o datos transferidos se llama Ancho de banda (Bandwidth), y en ambas plataformas te dan 100 GB gratis, lo cual alcanza para miles de personas al mes. En resumen: los minutos de compilación solo se gastan cuando tú haces cambios en el código y la plataforma tiene que procesarlos de nuevo.
